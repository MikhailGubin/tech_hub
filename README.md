# Веб-приложение "TechHub"

## Описание:      
    Данное веб-приложение является онлайн платформой торговой сети электроники.
    Содержит два отдельных приложения приложения: 
    "electronics" - приложение, в котором прописана основная логика приложения;    
    "users" - приложение для регистрации и авторизации пользователей, а также для настройки доступа для 
    авторизированных пользователей.

## Установка и настройка

### Предварительные требования

*   [Git](https://git-scm.com/downloads)
*   [Docker](https://docs.docker.com/get-docker/)
*   [Docker Compose](https://docs.docker.com/compose/install/)

### Клонирование репозитория

```bash
git clone git@github.com:MikhailGubin/tech_hub.git
cd <название_папки_проекта>
```
### Настройка переменных окружения

    Скопируйте файл .env.sample и заполните его:

```
cp .env.sample
```

    Откройте .env в текстовом редакторе и настройте переменные.

    Совет: Для генерации SECRET_KEY вы можете использовать команду Python:

```
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

### Запуск проекта
    С помощью Docker Compose
    Для запуска всех сервисов (PostgreSQL, Redis, Django Web):

```
docker-compose up -d --build
```

### Проверка работоспособности

#### Веб-приложение
    Для доступа к веб-интерфейсу приложения откройте браузер и перейдите по адресу: http://localhost:8000


#### Тестирование

    Для запуска тестов и проверки корректности работы всех компонентов выполните команду:

```
docker-compose exec web python manage.py test
```

#### Сервисы
    PostgreSQL:
    к базе данных, используя переменные из вашего `.env` файла:
    postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@localhost:5432/${POSTGRES_DB}
    Проверьте логи контейнера:

```
docker-compose logs db
```

    Redis:
    Проверьте логи контейнера: 

```
docker-compose logs redis
```

### Остановка проекта

    Остановка контейнеров
```
    docker-compose down
```

    Остановка и удаление данных (Полный сброс)
    ВНИМАНИЕ: Эта команда удалит все данные PostgreSQL и Redis!
```
docker-compose down -v
```

## Описание приложений:

1. #### Приложение electronics 
##### Описание:  
    Создана модель "Контакт" со следующими полями:
    
    * Почта 
    * Страна 
    * Город 
    * Улица 
    * Номер дома 

    
     Создана модель "Продукт" со следующими полями:
    
    * Название 
    * Модель 
    * Дата выхода продукта на рынок 


    Создана модель "Сетевое звено" со следующими полями:
    
    * Название
    * Контакты
    * Продукты
    * Поставщик 
    * Задолженность перед поставщиком в денежном выражении с точностью до копеек.
    * Время создания (заполняется автоматически при создании).
    
    Реализованы CRUD-операции для моделей Контакт, Продукт, Сетевое звено с использованием APIView.
    На странице объекта сети в админ панели добавлены:

    * ссылка на «Поставщика»;
    * фильтр по названию города;
    * admin action, очищающий задолженность перед поставщиком у выбранных объектов.  
    
    Для вывода списка сетевых звеньев настроена пагинация с выводом по 5 объектов на страницу.
    Для вывода списка контактов настроена пагинация с выводом по 7 объектов на страницу.
    Для вывода списка продуктов (товаров) настроена пагинация с выводом по 8 объектов на страницу.
    Проект содержит комплексные тесты, проверяющие CRUD-операции и бизнес-логику.
        
   
2. #### Приложение users 
##### Описание: 
    Создана модель «Пользователь» со следующими полями:   
    * Все поля от обычного пользователя, но авторизацию реализована по полю email;         
    * Город - город проживания сотрудника,
    * Фамилия — фамилия сотрудника
    * Имя — имя сотрудника  
    * Отчество — отчество сотрудника (опционально)
    * Должность — занимаемая должность в компании
    * Аватар — фотография сотрудника
    * Телефон — контактный номер телефона
        
    Электронная почта используется как поле для авторизации.
    Созданы CRUD для модели Пользователь. Для реализации CRUD использовано APIView.
    Каждый эндпоинт в проекте закрыт авторизацией, кроме регистрации и авторизации пользователей.
    В данном проекте использована JWT-авторизация.    
    Электронная почта используется как основное поле для авторизации.
    Реализована JWT-аутентификация с использованием Simple JWT.
    Созданы эндпоинты для регистрации, авторизации и управления профилем.
    
    Настроены права доступа:    
    * Информацию о сотрудниках могут просматривать все авторизованные пользователи
    * Редактировать информацию о сотрудниках могут только они сами или руководители.
    * Удалять пользователей можгут только руководители
